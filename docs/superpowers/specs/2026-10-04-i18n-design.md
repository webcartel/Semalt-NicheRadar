# i18n EN/UK — Design Spec

- Date: 2026-10-04
- Status: proposed, awaiting user review
- Approach: A — custom lightweight subsystem, no new dependencies
- Decisions (confirmed with user):
  - Default: browser language (`uk-*` → Ukrainian, else English), choice persisted in `localStorage`
  - State-only, no `/uk` URL prefix
  - Scope: static UI + locale-aware dates/numbers; API texts (niche names, `ai_summary`, categories in queries) stay English

## 1. Goals

- Full static UI in two languages: English (current strings, verbatim) and Ukrainian
- Language switcher in header, instant re-render, persisted choice
- `html lang`, page title and meta description follow the active language
- Dates (`Live since <Mon YYYY>`) and integer counts formatted per locale (`en-US` / `uk-UA`)
- Zero new dependencies; no backend/auth/DB; deploy-safe for Vercel/Netlify static presets

## 2. Non-goals

- No URL prefix, no routing changes, no SSR locale detection (client state only)
- No `@nuxtjs/i18n` module
- No translation of API data: `ai_categories` values in requests, category display names,
  product titles/domains, `ai_summary` stay exactly as returned
- Example search queries (`AI resume builder`, …) stay English (they are query values, not UI text);
  only the input placeholder/aria-label translate
- No pluralization library: audit shows numbers and labels are always separate elements
  (`10510` + static `matching / AI products`), so no Slavic plural forms are required.
  Ukrainian labels use number-invariant phrasing (`знайдено AI-продуктів`)

## 3. Architecture

New files:

- `data/i18n/en.ts` — `export const en = { key: 'English string', … } as const`
  (English strings copied verbatim from current code, no rephrasing per AGENTS.md wording rules)
- `data/i18n/uk.ts` — `export const uk: Record<I18nKey, string>` where
  `type I18nKey = keyof typeof en`. Missing/outdated keys fail `nuxt typecheck` — completeness
  is compiler-enforced, not convention-based
- `composables/useLocale.ts`:
  - `locale: Ref<'en' | 'uk'>` (global via `useState('locale')`, default `'en'`)
  - `t(key: I18nKey): string` — returns `dict[locale][key]`, falls back to `en` + `console.warn` in dev
  - `localeTag = computed(() => locale === 'uk' ? 'uk-UA' : 'en-US')`
  - `setLocale(l)` — sets state, persists `localStorage 'nicheradar:locale'`
  - `initLocale()` — once in `app.vue`: stored value → `navigator.language` (`uk-*` → `'uk'`, else `'en'`);
    invalid stored values fall back to `'en'`
  - `formatMonth(iso)` and `formatInt(n)` helpers using `localeTag`

Changed files:

- `app.vue` — header switcher (visible labels EN | UA, internal codes `en`/`uk`, radio-group), `useHead` sets `htmlAttrs.lang`,
  title and meta description from dictionary on locale change
- `pages/index.vue`, `pages/niche/[category].vue` — all static strings via `t()`
- `components/MarketHeatmap.vue`, `MarketPulse.vue`, `ProductCard.vue`, `MetricCard.vue` — labels via `t()`
- `DeltaPill.vue` — no change (renders only `±N%` / `—`)
- `composables/useNicheRadar.ts` — `searchError` stores an i18n **key** (`'errors.unavailable'`),
  components render `t(searchError)`; no API logic moves into components
- `nuxt.config.ts` — untouched (static EN head remains as SSR fallback; client `useHead` overrides after init)

Data flow: switcher click → `setLocale` → shared state → all `t()` recompute → `useHead` updates
`lang`/title/meta. First visit: `initLocale()` runs on app mount; SSR output stays English until hydration.

## 5. Error handling

- Corrupt/unknown `localStorage` value → `'en'`, no throw
- `navigator.language` unavailable (SSR) → config default until client init
- Missing key at runtime (should be impossible via types) → English fallback + dev `console.warn`
- Failed `useHead` update → page stays in previous language, no blank UI (dictionaries are local, no fetch)
